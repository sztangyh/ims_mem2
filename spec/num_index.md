# 号码索引设计（主叫 / 被叫）—— 草案 v1（待拍板）

> 目的：把「呼入主叫号码 → 甄别条目（含号码变化）」与「被叫字冠 → 多网元落地」两类高频查询
> 从**运行时逐跳匹配**变成**静态展开的有序索引**。本文只定义设计，不含实现。
>
> 数据背景（2026-11-15 实测，6 文件全量金标准）：
> - CLRDSN 26,875 行；**rdcx 非空仅 148 行且全部 FUNC=DSGATT**；FUNC 分布 DSG 26,328 / NIN 399 / DSGATT 148；
>   **全部落在指定甄别组（dsp=65534 通配组现网 0 行）**
> - CNACLD 79,669 行；SPCHG=SPCHG 仅 883 行（1.1%）；CLRAF=YES 54,030 行（主叫侧规整，不入被叫口径）
> - DNC 85 条：主叫侧用到的是 `INS 851` / `INS 844`（短号前插）；被叫侧多为 INS/RPL `0086xxx`（送出局形态）

## 一、主叫索引（ClrdsnIndex，per-NE）

**回答的问题**：给定一个主叫号码（或前缀），它命中哪条甄别条目？经 RDCX 变换后会变成什么？
静态展开后查询一次二分即得，不需要运行时再做"组内最长匹配 + 杜恩查变换"。

### 1. 条目形态

```
item: {
  seg:      (lo: NumKey, hi: NumKey),   // U4Number 域的半闭区间；段集合互斥
  ne_idx:   u32,
  row:      u32,          // CLRDSN 原始行位置（"索引指向 ne 和 clrdsn 位置"）
  dsp:      u32,
  func:     FUNC,         // DSG/NIN/DSGATT…
  after:    Option<NumKey | Seg>,  // 变换后形态（rdcx 应用的结果；None=无 rdcx，条目即原样段）
  min_max:  (u8, u8),
}
```

有序数组按 `seg.lo` 排序；查询 = 二分定位包含目标号的段。

### 2. 构建算法（三步）

**第 1 步 · 段展开**：每条 CLRDSN `(cli, min, max)` 展成号码段集合
`Segs(cli) ∩ len∈[min,max]`。用户例：`cli=2, min=max=2 → [20, 29]`；
`cli=22, min=max=2 → [22, 22]`。min=max=255（不甄别）时按"cli 前缀、任意后缀"的开放段处理。**实测现网以定长为主**（样例 min==max）。

**第 2 步 · 组内最长匹配静态化（减法）**：同一 `(ne, dsp)` 组内，把长的具体 cli 先占号，
泛 cli 的段集减去已占部分 —— 即"2 包含 22 时，2 替换为 2−22：

```
cli=2  的段 [20,29]  −  cli=22 的段 [22,22]
= [20,21] ∪ [23,29]     （剩余 2 位窗内的 9 个段）
```

减法语义依据：ADD CLRDSN「最大匹配」（文档原话：组内配 13/139/1390 时，13901234567 命中 1390
而非 13/139）—— 静态展开 = 预计算最大匹配的归属，泛条目只保留"它实际负责的部分"。
跨组不做减法（不同 dsg 服务不同中继；DSP=65534 通配组存在"指定组优先"规则，现网 0 行，见待拍板 2）。

**第 3 步 · RDCX 变换展开（148 条）**：段继承原条目的 rdcx；**变换能作用于确定前缀的，产出
"变换后主叫"段替代原文放进索引**：

- `INS（前插）`：段前缀前插 nd，min/max 各 +len(nd)。实测主叫侧全部是 INS（851/844），
  即"5 位短号 → 851xxxxx/844xxxxx 补齐到 8 位"的静态化；
- `DEL / MOD（dcp+dcl ≤ len(cli)）`：删/换发生在确定前缀内，段可确定重算；
- 变换作用在**活动长度区**（延伸进 min~max 的活号码）的：静态不可确定 —— 记 `partial`
  例外计数并保留原文段（当前实测 **0** 条，规则留位）；

> **变换后形态进目录（决议 3）**：`INS 851/844` 产生的 `851xxxxx/844xxxxx` 段作为独立目录条目，
> 目录 = 原文 + 变换后形态的号码字面全集。

### 3. 查询形态

| 查询 | 用途 |
|---|---|
| `exact/near(num)` | 主叫号码 → 唯一归属段 → 甄别条目 + 变换后形态 |
| `under(prefix)` | 某主叫前缀下的主叫空间（含 rdcx 变换后形态） |
| `by_dsp(dsp)` → 段集 | 该甄别组（= TGDSG 关联的中继）的全部主叫空间 |

> 主叫侧同样存在号首形态（实测：裸 22,454 / `86*` 4,400 / `0*` 21）—— 原文/别名原则与
> §三·补 一致（`0+X` 生成别名；`86*` 待确认），`exact/longest` 同样只用原文。

### 4. 规模预估

26,875 行（含减法分裂）→ 段数 < 5 万；每段 17B key + ~16B 载荷 ≈ **1.5 MB**（全部 6 NE 合计），

## 二、被叫索引（CalleeIndex，全局聚合）

**回答的问题**：给定被叫字冠（或一串拨号），在哪些网元有配置？**各局是否落本地（DOL=LOW）**？

### 1. 条目形态

```
item: {
  pfx: NumKey,
  sources: Vec<Source>,   // 相同 pfx 跨网元聚合；"vec 里有来源的位置 + 在此网元是否有落地"
}
Source: { ne_idx, row, lands_local: bool, minl, maxl, rsc }
```

### 2. 落地标志的判定链（构建期一次算好）

```
CNACLD(pfx, rsc)
  → RTANA(rsc → r…)          一键多行是契约（R8），全展开
  → RT(r → sr1..6)
  → SRT(src → o)             子路由指定局向
  → OFC(o → dol)
lands_local = 存在一条链上 OFC.DOL == 'LOW'
```

OFC.DOL（对端局级别）：HIGH 上级局 / SAME 同级局 / **LOW 下级局（=落地局向）**。
numtrace 现行口径 `dol != 'LOW'` 即从这里来。链路上各表量级：rtana 1,924 / rt 1,914 /
srt 2,188 / ofc 1,974 —— 单 pfx 展开几十跳以内，构建期全量预算 < 1s。

### 3. 被叫侧**不做**号码变化展开（口径拍板依据）

| 参数 | 实测 | 结论 |
|---|---|---|
| SPCHG（按 pfx 重查 SPDNC） | 883/79,669 = **1.1%**；变换形态 = RPL/INS `00867574464xx`（送出局） | 变换后仍出局，**不改变"是否落本局"**；且按完整被叫号码重查，静态无意义 |
| CLRAF（重查 CNACLR） | 54,030 行 YES，但做的是**主叫侧**规整 | 不入被叫索引 |
| SPCDAF / CLII | 0 / 0 | 未用 |
| QCDN+QMODE+QLENGTH+DCINDEX | 0 | 未用 |

号码形态细节（变换成什么送出局）仍由 Transform IO / PrefixLookup 下钻按完整号码现算 ——
静态索引只回答"落不落本局 + 指向原位置"。**但 SPCHG 变换后的号码形态（如 `0086757446433`）本身
要进目录（决议 3）** —— 它是用户可能查询的字面，只是不用于落地判断。

### 4. 规模预估

distinct pfx ≈ 56,310（prefix 池实测）× (17B + sources 8B×平均 1.4) ≈ **1.5–2 MB**。
两索引合计 ≈ **4 MB ≈ 正文 3%**，在 D63 预算（<10%）之内。

## 三·补 · 号首形态（冠码别名）设计（2026-11-15 定案）

> 问题（用户提出）：输入字冠带不带区分——`0086755 / 0755 / 755` 三种形态。查询时是把输入
> **规整成带区分**再查，还是**索引表的字冠相应处理**（剥冠）？

### 0. 实测形态全景（行口径，金标准）

| 表 | 主形态 | 量级 | 次形态 |
|---|---|---|---|
| CNACLD.PFX（被叫） | `0086*` **50,035 行（62.8%）** | distinct 25,077 | 裸 27,982（多为 `44xxxxx` 变换后目的地）；`0*` 1,548（`0755` 系）；`86*` 84；`00*非0086` 20 |
| CLRDSN.CLI（主叫） | 裸 **22,454（83.5%）** | — | `86*` **4,400**（`86000022` 系）；`0*` 21 |
| TGLDIDX.PFX（变换） | `0086*` 4,457（85.9%） | — | 裸 725（`2/4/6/8`）；`0*` 8 |

**关键事实：等价并存不存在** —— `0086X` 剥 0086 后，裸形态 exact 并存 = **0**（前缀并存仅 1）；
`0X` 剥 0 后并存 77/538。⇒ 各形态是**独立配置**（不同接入路径、不同落地/路由），不是同一配置的多重写。

### 1. 三条核心原则（定案）

1. **索引/目录永不归一、永不丢原文**。形态是配置语义的一部分（`0086755235165` 的国际落地与
   假想的本地 `755235165` 是两码事）；实测"剥后裸并存=0"证明归一会混同**本来就不存在对应关系**的配置。
   —— 索引表**不做**"字冠相应处理"（剥冠改写）。
2. **形态无关性靠"别名键"（构建端派生，保留原文）**：对每个带冠键生成剥冠别名条目，
   与原文条目共存于同一排序数组。**输入不需要规整**——输 `755` 前缀查即同时看到
   `755*`（原文）与 `0086755*`、`0755*`（别名条目，回显原文形态）。别名条目 `alias_of` 指回原文键，
   同一别名可挂多源（`0086755110` 与 `0755110` 剥出同一 `75511x` 是正常形态，多源并列）。
3. **exact 与 longest 永远只用原文键**。运行时语义 = 送来什么形态就匹配什么配置；
   别名只服务"人查"（目录/探索），**不服务运行时模拟**。正确性边界，写死。

### 2. 查询语义表

| 查询类型 | 原文键 | 别名键 | 说明 |
|---|---|---|---|
| `catalog` prefix/tail（fzf 目录） | ✓ | ✓（条目标 `alias`+`alias_of`） | 人查要形态无关 |
| `catalog` exact | ✓ | ✗ | 精确找配置 |
| `longest`（被叫最长匹配/运行时模拟） | ✓ | ✗ | 形态即路径 |
| `under` / `range`（号段统计） | ✓ | ✗ | 统计原文配置 |

### 3. 别名规则（v1，按实测限定）

| 规则 | 覆盖 | 备注 |
|---|---|---|
| `0086 + X → X` | 被叫 50,035 行 / 变换 4,457 行 | 主规则；输 `755` 能见 0086755 系 |
| `0 + X → X`（非 `00` 开头） | `0755` 系 1,548 + 主叫 21 | 国内长途冠码 |
| `86 + X → X` | 主叫 4,400 / 被叫 84 | **已确认**（用户拍板：86 是国家区号；`86000022 → 000022` 按裸段查，成本接受） |
| `00+国家码`（非 0086，不定长） | 仅 20 行 | **登记先不做**（用户裁定） |

> **一级剥离 = 保留区号**：`0086755xyz → 755xyz`（剥 0086）。用户输入 `755 / 755x / 755xyz` 即命中。
> **裸段（去掉区号）的反查 —— 定案用「查询端补全」而非「索引端二级剥离」**（见下）。

### 3.5 形态归一 —— 对称剥冠（2026-11-15 二次定案：取代"查询端补全"）

> 用户拍板方向："问题回到索引表找办法"。**索引端与客户端用同一个剥冠函数**，索引剥到**裸核心**
> （冠+区号全剥），客户端把输入也剥成核心去查 —— 两端规则对称，无需补全集合、无需意图猜测。

**冠前缀集合 P（长优先）**：`0086755` / `86755` / `0755` / `755` / `0086` / `86` / `0`
（深圳区号 755；可配）。

**统一函数** `strip(s)`：
- `s` 是某冠的前缀（含恰为冠，即**过程态**：`7/75/755/8/86/867/8675/0/00/008/0086/07/075/0755…`）→ **原样**（"正在打冠"阶段：查原文池，命中该冠系原文，如 `755` 恰为冠 → 命中裸 755 形态 4 条 + 前缀系）
- 否则剥**最长**匹配冠 → 核心查询；无冠可剥 → 原样（本地号）

**索引端**：对每个原文 pfx 生成核心别名（`0086755xyz→xyz`、`0755xyz→xyz`、`755xyz→xyz`、
`0xyz→xyz`、`86xyz→xyz`、`86755xyz→xyz`），**核心键挂所有原文形态**（多源并列）；
原文键同时保留（过程态查询的落点）。
**客户端**：输入过 `strip()` 再查 —— 一个输入形态只产生**一个查询键、一次请求**。

**实测验证**（temp/q_core_sim.py，全量金标准）：
- 池 = 原文 56,310 + 核心别名 **63,872 键**（净增 7,562；核心大量与原文键重合）；别名条目 ≈ 30,000，**+0.5 MB**（17B/键）
- **'7' 命中 43 条**（旧补全方案 25,543，**噪声 −99.8%**）；命中全是核心 7 开头的真条目
- **`7552` / `00867552` / `07552` 剥后同查 `2`** → 命中 24,280（一次请求；旧方案需 4 形态合并）
- `7552`（区号路径）与 `2`（本地路径）**命中相同** —— 核心视图=号码本体视图，殊途同归，
  正好符合"目录=号码形态全集"（决议 3）
- `0086755`（恰为冠）原样查 → 25,074（= 0086755 系原文，"打完区号看看有什么"的自然语义）
- `075582001` → 查 `82001` → 6 条：`008675582001577` 与裸 `75582001577` **同键命中**
  （clrdsn 裸 755 形态特例被对称剥冠自动覆盖，无需单列规则）
- `8626` → 查 `26` → 3,695（86+外地区号路径正常）；`867/8675` 过程态原样（命中 4/2 条）
- 上轮意图问题自动消解：`00867557→查7`、`07557→查7` —— 即"755 区号接 7 字头"的所有形态一次命中

**展示口径（用户拍板，2026-11-15）**：**服务端排序/查询匹配用别名（核心键），客户端目录列出的一定是原字冠**。
- **目录条目 = 原字冠，核心键只作匹配/排序维度**：命中核心键 → 在响应里**展开为该核心的全部原字冠形态**，
  **每个原字冠一条**（同核心的形态相邻，排序键=`(core, orig)`）；
  命中原文键（过程态查询）→ 条目即该原文字冠。
- 每条条目带自己的 `roles/nes/hits`（按原字冠算）与 `id = prefix|原字冠` —— 结构与现有目录条目一致；
  可附带 `core` 字段供 UI 标注"同核心多形态"分组。
- `total` = 展开后的原字冠条目数（用户看到的条目数，非核心键数）。
- **游标**：keyset 二级 `(core, orig)` —— 同核心下按原字冠字典序，翻页无重无漏。
- **选中后 object.get 用原字冠**（对象世界的键永远是原文形态）—— 与"exact/longest 只用原文"
  的正确性边界一致；别名不外泄为业务键。

**边界登记**：
1. **86 的过程态**：`86/867/8675` 原样查（`86` 是 86…区号形成中）；实测 `86` 原样命中 8,719 条
   （核心 86 开头 = `0086755|86…` 剥出），语义="86 开头核心视图"，可接受。
2. **`86` 冠两义**（86=国家码 vs 0086755|8 字头）：剥冠后同键并列，命中带形态标注可区分。
3. **区号假设**：P 集内置 755（深圳）；跨地市部署时 P 可配。本地真有 755 开头字冠会与区号剥混同（现网裸 755 开头仅 clrdsn 4 条且即区号形态，判定安全）。

### 4. 代价与预算

对称剥冠口径（temp/q_core_sim.py）：池 = 原文 56,310 + **净增核心别名 7,562** = 63,872 键
（核心大量与原文键重合——裸原文即自身核心）；别名条目 ≈ 30,000 → **+0.5 MB**。D63 预算内。

## 四、已拍板决议（2026-11-15）

> 1–4 对应上一版"待拍板"；领域核实见正文。

1. **全局 trunk 表**：**内存目前没有全局 trunk 表** —— `TrunkIndex`（trunk.rs）是 per-NE 的（`NeStore.trunks`，
   `build_for(&ne)`），只聚合本网元的 PRATG/N7TG/SIPTG 公共属性。**后期构建全局 trunk 表**，
   **`dsp`（甄别组号）作为 trunk 属性** —— 领域来源是 `TGDSG.DSG → CLRDSN.DSP`（refs_gen 已建模该边；
   TGDSG 列 `tg/dsg/tgn`，键 tg），即中继 → 其主叫甄别组。全局 trunk 表 + dsp 属性天然支撑
   "中继 → 它放行的主叫空间"（经 dsp 关联主叫索引条目），**无需另建二级索引**。
2. **65534 语义澄清**：**65534 不是字冠通配，是甄别组号（DSP）通配**（"组号 65534 为通配符，可为任何
   入中继群使用，优先级最低"）。**通配组条目不加入目录**；实现档位取 A（现网 0 行，不实现、
   出现即在导入统计告警）。若将来现网出现，按文档"指定组优先 + 同时索引两组"规则再并入匹配空间。
3. **目录要全 —— 变换后的号码形态进目录**：主叫 RDCX 变换后（`851xx`/`844xx`）**作为独立目录条目**；
   **其它类似的变化后号码同样进目录**（目录 = 所有可能被查询的号码形态集合：原文 + 各变换形态）。
   即目录覆盖"号码字面全集"，不限于落地判断用的形态。被叫侧 SPCHG 变换后（如 `0086757446433`）
   虽**不进落地判断**（静态口径），但**其形态仍要进目录**（用户会搜这个号）。
4. **落地标志**：**构建期算好**（写进 sources 每项），查询零成本；规模预算（正文 3%）已含。
